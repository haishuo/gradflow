# Academic A3 independently validated differentiation result

Status: **complete on the primary Forge machine**.

Date: 2026-08-30 (UTC)

## Result

GradFlow recovered an unknown linear-advection speed by reverse-mode
differentiation through a complete 16-step, order-11 FD-WENO-JS SSP-RK3 solve.
Starting from `c=0.8`, LBFGS recovered `c=1.1000008465` from sixteen analytic
terminal observations; the known truth was `1.1`. An independent
derivative-free golden-section search returned `1.0999999951`, so the two
inverse answers differed by `8.51e-7`. The objective fell by approximately
`1.02e11` from its initial value. The frozen gradient, inverse, device,
compiler, and timing gates all passed.

This demonstrates bounded differentiable utility. It is not a claim that
GradFlow invented differentiable WENO or WENO-based inverse inference.

## Problem and independent authorities

The frozen problem is positive-speed periodic linear advection on `[0,2*pi)`:

```text
u_t + c u_x = 0,       c_star = 1.1,       T = 0.125.
```

The initial condition contains four nonsymmetric Fourier components. Sixteen
uniformly spaced terminal sensors are compared with the analytic continuum
solution `u_0(x-c_star*T)`. The numerical solve uses exact-generated WENO-JS11,
explicit `alpha=c`, float64, unique periodic nodes, and fixed-step SSP-RK3.

Three authorities are deliberately distinct:

1. the continuum solution supplies observations and the true parameter;
2. centered finite differences check the derivative of the discrete objective;
3. a derivative-free golden-section search checks the gradient optimizer's
   discrete minimizer.

No target observation was generated by GradFlow, and no canonical numerical
source changed.

## Execution cost

Times are medians of 20 retained observations after three warmups. CUDA inputs,
target, parameter, result, and gradient remain device-resident. Compilation
used a separate initially empty TorchInductor cache per worker.

| Device/lane | Forward objective | Objective + gradient | Gradient/forward | First objective + gradient |
| :--- | ---: | ---: | ---: | ---: |
| CPU eager | 98.749 ms | 284.560 ms | 2.882x | 0.256 s |
| CPU compiled | 2.109 ms | 3.831 ms | 1.817x | 504.493 s |
| CUDA eager | 215.260 ms | 631.664 ms | 2.934x | 0.753 s |
| CUDA compiled | 4.437 ms | 10.951 ms | 2.468x | 339.093 s |

Compiled execution is dramatically faster than eager after preparation:
`74.3x` for CPU objective-plus-gradient and `57.7x` for CUDA. At this small 1-D
problem, compiled CPU is `2.86x` faster than compiled CUDA, consistent with
A2's conclusion that GPU use is not automatically beneficial.

Compilation dominates a short inverse solve. Based only on median
objective-plus-gradient savings, the observed compilation cost corresponds to
roughly 1,797 evaluations on CPU and 546 on CUDA. The demonstrated LBFGS solve
used only 11 closure evaluations, so eager CPU is the sensible one-off path
here. Long optimization campaigns or repeated inverse jobs can change that
economics, but A3 does not implement an automatic selector.

CUDA peak allocation/reservation during the complete worker was `53.5 MB /
56.6 MB`. Host compiler peak memory was not instrumented; process observation
during the run showed substantial compiler work, but no memory claim is made
from that diagnostic.

## Scientific interpretation

1. GradFlow's differentiability is useful beyond a local `gradcheck`: it can
   recover a PDE parameter through an actual time-integrated WENO solve.
2. Agreement with centered finite differences validates the derivative of the
   implemented discrete function, while the analytic truth and derivative-free
   optimizer independently validate the application result.
3. Reverse mode costs about `1.8x--2.9x` the corresponding forward objective
   after preparation for this scalar-parameter problem.
4. Whole-solve compilation can provide enormous warm speedups but can be a bad
   deployment choice when compilation is charged and few gradients are needed.
5. GPU acceleration is workload-dependent: this small 1-D float64 inverse is
   faster on compiled CPU, even though CUDA compilation and differentiation
   are correct.

## Boundaries

This result does not cover shocks, discontinuities, noisy observations,
negative or branch-changing speeds, adaptive timesteps, long/chaotic
horizons, checkpointed adjoints, mixed precision, characteristic Euler inverse
problems, DVEB/native gradients, arbitrary boundaries, or a general inverse
PDE product. The absence of those claims is part of A3's result, not work
silently treated as complete.
